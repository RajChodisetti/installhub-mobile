## Financial field and payload mapping

The typed response is [FinancialSummary / FinanceHeader / CostLine](../src/types/commercial.ts). The portal comparison is `finance/FinancialSummaryPage.tsx`, `FinanceHeaderForm.tsx`, `CostLinesPanel.tsx` and `finance/api.ts`; server guards and validation are in `src/routes/installhub/finance.ts` in the API repository.

| Section | API fields / values | Native rule / action |
| --- | --- | --- |
| Installation context | `installationId`; `installation.{siteName,clientName,siteAddress,status}` | Response installation ID must equal the route. Use the backed-up current installation ID; do not substitute an imported cpN source ID. |
| Price | `header.{installationId,pricingMode,pricedAmount,currency,notes,updatedAt}`; mode `quoted` or `charge_up`; amount `number|null`; notes `string|null` | Header editor retains server data/defaults. Quoted amount uses nonnegative cent validation; empty nullable capture stays null. `PUT I/finance` sends `{pricingMode,pricedAmount,currency?,notes?}`. |
| Cost capture | `category`: `labour`, `material`, `other`; `description`, `costAmount`, nullable `sellAmount`; `billable`; optional nullable `incurredAt` is accepted by the typed API but has no capture control here | `POST I/cost-lines` from both UIs sends category, trimmed description, cost, nullable sell and `billable:true`. Native validates finite nonnegative cent amounts. Neither client sends `hours` or `invoiced`; those authoring controls were removed. |
| Cost history / ownership | `id`, `installationId`, `source`: `manual` or `auto_labour`; `createdByUserId`, `createdAt`, `updatedAt`; returned nullable `hours`, `billable`, `invoiced` | Render server values and read-only flags; line IDs must belong to current installation. Expense hours currently return null. Draft reservation, issue and void govern invoice state; there is no manual toggle. Manual-line Delete uses the same ID; auto-labour cannot be manually deleted. |
| Position | `billablePricedAmount`, `invoicedCosts`, `uninvoicedCosts`, `uninvoicableCosts`, `totalCurrentCosts`, `potentialProfit`, `creditApplied` | Display server-calculated currency values. The API's `uninvoicableCosts` spelling is retained. |
| Margins | Nullable `billablePricedMarginPct`, `currentMarginToDatePct`, `marginBreathingRoomPct` | Display nullable server percentages; do not reinterpret unavailable margins as zero. |
| Billing totals | `invoicedBillable`, `uninvoicedBillable`, `currency` | Display server currency/amounts; invoice actions stay API-authoritative. |
| Labour and categories | `labour.{cost,sell,hours,unchargedCost}`, `material.{cost,sell}`, `other.{cost,sell}`, `scheduledHours` | Preserve returned totals and units. Displayed labour hours use audited cost hours/default zero; labour sell uses audited billable quantity and resolved billing rates. App-active time does not populate either value. No local balance calculation or hours editor. |
| Automatic labour | `autoLabour.{enabled,hoursPerDay,hourlyRate,calendarDays,hours,costAmount,startAt,endAt}` | Show returned automatic-labour context and source; do not invent/edit derived labour rows. |
| CSV | `GET I/financial-summary.csv` | Authenticated download and native sheet use the calling screen's lease. Decoded compression length handling, complete-stream validation and temporary-file cleanup apply. The exact build-six export is recorded in the master; no recipient was selected. |

## Invoice field and payload mapping

The typed response is [Invoice / InvoiceListItem / InvoiceLine](../src/types/commercial.ts). Portal references are `invoices/QuickInvoicePanel.tsx`, `InvoicesPage.tsx`, `InvoiceDetailPage.tsx` and `invoices/api.ts`; the API owns status transitions and financial history.

| Section | API fields / values | Native rule / action |
| --- | --- | --- |
| Identity/status | `id`, `installationId`, `invoiceNumber`, `status`, `currency`, `createdAt`, `updatedAt` | Preserve `draft`, `issued`, `paid`, `void`; paid exists in the API even though the original portal type omitted it. Select by stable IDs, not number/label. |
| Dates | Nullable `issueDate`, `dueDate`, `issuedAt`, `voidedAt` | Display returned dates/status history. Do not create a date-edit control solely because the API's draft PATCH accepts `dueDate`. |
| Bill-to | `installation.{auditDate,siteName,clientName,siteAddress,status}` | Display the invoice response's installation context. |
| Seller/history metadata | Nullable `sellerName`, `sellerAbn`, `sellerAddress`, `sellerEmail`, `createdByUserId`, `notes` | Preserve typed response metadata used by detail/PDF; not every API property is an editable portal field. |
| Lines | `id`, `invoiceId`, `sortOrder`, `description`, `quantity`, `unitAmountExGst`, `lineTotalExGst`, nullable `costLineId`, nullable `category` | Render quantities, unit amount and exact line total in returned order. Reject foreign invoice line IDs before displaying actionable detail. |
| Totals | `subtotalExGst`, `gstAmount`, `totalIncGst`, `gstRate` | Quick preview shows ex-GST, 10% GST and total as the portal does; saved invoice uses returned server values. |
| Eligible costs / draft creation | `costLineIds?:string[]`, `notes?:string|null` | Choose billable uninvoiced source costs; retain selection/notes locally until action; `POST I/invoices/quick` returns the created invoice. Success navigation is fenced to the originating actor/record/focused screen. |
| Lifecycle | `POST I/invoices/:invoiceId/issue`; `POST .../void`, no body | Issue only draft; void confirmation for nonvoid; already-void record has no repeated lifecycle/download action. Server errors remain visible. No client payment or email operation is invented. |
| PDF | `GET I/invoices/:invoiceId/pdf`, binary MIME and disposition | Caller-bound authenticated download, safe unique temporary file, native share and cleanup. Source/local byte tests do not prove this invoice PDF works on device. |
