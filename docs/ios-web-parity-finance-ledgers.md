# Finance ledger contract correction

Both the portal Field App and iOS financial summary exposed editable expense hours and a manual invoiced toggle that the current dedicated API rejects. `installHubFinanceService.createCostLine` rejects non-null hours or truthy invoiced; `updateCostLine` rejects either property. The legacy rejection string refers to an immutable active-work ledger, but that string is not the authority for financial values: `schedulerFinanceService.buildFinancialSummary` keeps app-active time as internal evidence. Cost hours and billable hours come from separately audited overrides or default to zero; they are not populated from app-active time. `sharedSummaryToLegacy` displays `shared.time.costHours` as labour hours and leaves expense hours null. Labour revenue uses the audited billable quantity and resolved user billing rates. Invoice draft reservations, issue and void own invoice state.

The iOS correction keeps audited labour hours and each expense's invoice state visible, removes those two invalid authoring controls, and omits the ledger-owned properties from cost request types and payload construction. Valid category, description, cost, sell and billable cost creation/deletion remain available. Pricing and notes are preserved. The companion portal correction belongs to `apps/ecoaudit/src/modules/installhub/finance/CostLinesPanel.tsx`; no API ledger relaxation is intended.

Verification: 32 focused native commercial tests passed, including actual screen render/submit handlers against a rejecting ledger boundary, excess legacy-input filtering, existing commercial scope/file tests and support contract tests. TypeScript typecheck passed. No physical finance/invoice mutation, portal build or live API success is claimed by these checks. Native QA draft/issue/PDF/void remains a separate exact-synthetic-fixture gate.
